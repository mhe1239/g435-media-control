# 작업 기록 - Android 전환과 입력 출처 확인

- 기록 일시: 2026-10-31 13:47 기준 문서화, Asia/Seoul
- 실제 작업 시각: 사용자 제공 로그 2026-09-19 17:21:32.928–17:22:11.435 (+09:00); 앱 작성·설치의 정확한 시각 미상
- 작성자/에이전트: Codex, 대화의 사용자 로그와 현재 코드 기반 복원
- 작업 유형: Android 진단 앱 개발 / 실기기 관측

## 요약

갤럭시에서 MediaSession으로 버튼 신호를 확인하는 방향을 선택했다. USB 디버깅과 앱 실행을 안내하고, 사용자는 휴대폰과 G435의 버튼을 눌러 시험했다.

## 변경 범위와 주요 파일

`android-signal-probe`의 플랫폼 Java Activity, MediaSession, VolumeProvider 기반 진단 앱을 준비했다. 입력 장치 이름·descriptor·vendor/product 등을 함께 기록하는 기능이 현재 코드에 있다. 이 기능을 추가한 개별 시각은 불명확하다.

## 관측과 검증

- 반복적으로 “수신된 이벤트가 없습니다”가 표시됐다고 사용자가 보고했다.
- 사용자가 붙인 로그에는 `KEYCODE_VOLUME_DOWN`/`UP`, `activity_key`, `volume_provider`의 DOWN/UP/SAME이 있다.
- 해당 로그의 deviceId는 5와 2지만 이름 정보는 없다. 번호만으로 G435 발생 이벤트라고 확정할 수 없다.
- 이후 2026-10-14 별도 로그에서는 `name=gpio-keys`가 확인돼 그 특정 입력은 휴대폰 본체 버튼으로 구분했다. 이 결과를 9월의 모든 deviceId에 소급하지 않는다.

## 리스크/이슈

MediaSession 활성 상태가 실제 미디어 버튼 수신 대상임을 보장하지 않았다. 이후 Samsung Music 등이 미디어 버튼 세션을 유지하던 상황을 점검했다. 최근 앱 목록에 보이지 않는 것과 세션 해제는 같지 않다.

제안한 짧은 동시 누름을 Android가 이벤트로 받는지 확인하지 못했으며, 재매핑 로직은 구현하지 않았다.

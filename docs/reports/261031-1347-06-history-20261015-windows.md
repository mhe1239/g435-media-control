# 작업 기록 - Bluetooth PC 재시험과 볼륨 누락 보고

- 기록 일시: 2026-10-31 13:47 기준 문서화, Asia/Seoul
- 실제 작업 시각: 2026-10-15 00:00:32.137 이후; 주요 관측 00:07:39.320 / 00:07:44.216 (+09:00). 그 뒤 사용자 증상 보고의 정확한 시각 미상
- 작성자/에이전트: Codex, 현재 Windows JSONL과 과거 대화를 대조해 복원
- 작업 유형: Windows 실기기 재시험 / 진단기 보완

## 요약

사용자가 LIGHTSPEED 동글 없이 PC Bluetooth에서 시험하자고 요청했다. 연결을 확인한 재시험에서 볼륨 +/− 순서와 맞는 Windows 오디오 변화가 두 번 기록됐다. 직접 버튼 키나 안정적인 재매핑은 확인하지 못했다.

## 00:00–00:04: 첫 실행과 연결 혼선

- 00:00:32.137 진단 시작. baseline은 G435 `Unplugged`/`NotPresent`였다.
- 사용자는 휴대폰 Bluetooth 해제, PC 연결, 짧은 단독/동시 누름 순서로 시험하도록 안내받고 완료를 알렸다.
- 00:01:32.116의 `candidate=true` 키는 `0x12`(Alt), `0x09`(Tab)이었다. G435 미디어 입력으로 판단하지 않았다.
- 00:02:52.626의 볼륨 `0.43307 → 0`은 `Unplugged` 엔드포인트였다. 성공 관측에서 제외했다.
- 별도 상태 조회에서는 활성 엔드포인트를 확인했으나 첫 실행 기록으로 버튼 효과를 확정하지 않고 재시작했다.

## 00:05 이후: 연결 확인 후 좁힌 재시험

진단기에 `audio_state_change` 기록을 추가하고 `python -m py_compile` 성공을 확인했다. 기존 관측 프로세스를 종료한 뒤 재실행했다.

| 로그 시각 | 관측 |
|---|---|
| 00:05:00.572 | 진단기 시작 |
| 00:05:01.586 | G435 헤드폰 Active, mute=false, volume=0.43067 |
| 00:05:01.587 | G435 마이크 Active, mute=false, volume=0.41961 |
| 00:07:37.299–.301 | Logitech 후보 장치의 Alt·Tab; G435 버튼 증거에서 제외 |
| 00:07:39.320 | Active 헤드폰 volume 0.43067 → 0.49342 |
| 00:07:44.216 | Active 헤드폰 volume 0.49342 → 0.43067 |

사용자는 G435 +, −, 음소거를 각각 약 3초 간격으로 누르는 시험을 완료했다고 알렸다. 두 볼륨 변화는 시험 순서와 맞았다. 해당 구간에는 G435라고 입증된 키/HID나 `audio_mute_change`가 없다. 관측 프로세스는 이후 종료했으며 `Stop-Process`를 사용했으므로 JSONL의 `stopped` 행 유무와 동일시하지 않는다.

## 이후 사용자 보고와 아직 열린 질문

사용자는 “G435의 +/−를 눌러도 볼륨이 안 올라갈 때가 있다”고 추가로 보고했다. 그 뒤 조회에서 기본 출력은 G435, 헤드폰 Active, volume=0.37565였으나 실패 시점과 대응하는 기록은 아니다.

마지막 질문은 “Windows 볼륨 숫자도 그대로인가, 숫자는 변하는데 실제 소리만 그대로인가?”였다. 답변과 재현 로그는 아직 없다.

## 리스크/이슈

두 번의 볼륨 변화는 제한적인 성공 관측이다. 물리 버튼 식별이나 반복 누름의 신뢰성을 보장하지 않으며 다른 앱의 음량 변경과 혼동할 수 있다. 최소/최대 음량, 헤드셋 내부 음량, Bluetooth 동기화, 오디오 경로, 폴링 누락은 원인 후보일 뿐 미확정이다.

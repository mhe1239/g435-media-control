## 요약

“G435 +/−를 눌러도 볼륨이 안 올라갈 때가 있다”는 증상을 Bluetooth 연결 PC에서 재현했다. 사용자 답변상 실패 시 Windows 볼륨 숫자도 바뀌지 않는다. 이번 시험에서는 + 4번 뒤 헤드셋이 “따닥” 소리를 내고 더 올라가지 않았으며, 그때 Windows 값은 `0.69167`(69%)이었다. 무반응은 버튼 신호 누락보다 **G435 자체 최대 음량 도달**로 설명된다.

## 변경 범위와 주요 파일

- 코드 변경 없음. [진단기](../../g435_signal_probe.py)를 그대로 실행했다.
- 원본 증거: [g435-signal-log.jsonl](../../g435-signal-log.jsonl)의 2026-10-31T19:57–20:00 구간.

### 강의 재생 중 시험 (2026-10-31 20:09:33–20:11)

- 사용자가 대학 강의 사이트로 강의를 재생하며 G435 +/−를 눌렀다. 사용자 관측상 음질 저하나 먹먹해짐은 없었다.
- tested: 헤드폰 엔드포인트는 계속 `Active`였고 Hands-Free 전환은 재현되지 않았다. 20:09:37–20:10:10 볼륨 변화 19건이 모두 한 단계씩 고정 단계값으로 기록됐다.
- 이번 실행은 Hands-Free 조회 오류가 0건이었고 기록 간격이 약 1초였다. 앞 실행의 약 2.7초 간격은 오류 처리로 조회가 느려진 탓으로 보인다(unverified).
- 20:10:38–20:10:43의 볼륨 변화(`0.58441` 등 단계표 밖 값)는 G435가 아닌 다른 BLE HID 장치(`VID&023554_PID&fa07`, HID over GATT)의 Consumer Volume Increment(`0x00E9`) 리포트와 같은 시각이다. G435 증거에서 제외한다.
- Windows 마이크 사용 기록(`CapabilityAccessManager\ConsentStore\microphone`)에 2026-10-31 사용 항목이 없었다. Chrome 최종 사용은 10-17이다. 다만 오늘 이후 날짜(11-07) 항목이 있어 이 기록의 시각은 신뢰도가 낮다.

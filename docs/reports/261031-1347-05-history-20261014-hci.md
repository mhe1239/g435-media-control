- 실제 작업 시각: 2026-10-14 23:50:39 버그리포트 이름 기준, 수집은 수분간 진행

- 작업 유형: 원시 통신 진단 / 과거 판단 정정

## 요약

앱에서 입력을 찾지 못하자 사용자가 더 낮은 계층의 관측 가능성을 물었다. 개발자 옵션에서 Bluetooth HCI 스누프 로그의 `사용 설정됨`을 선택하고 Bluetooth 재시작·재연결 후 버튼을 시험하도록 안내했다.

## 수집 경과

- 표준 global 설정 조회는 `null`이었다. 이것만으로 삼성 기기의 HCI 로그 활성 여부를 판정하지 못했다.
- REA의 버그리포트 수집 결과 ZIP 크기는 35,477,704 bytes였다.
- 당시 경로는 `diagnostics/hci/dumpstate-2026-10-14-23-50-39.zip`이다.
- ZIP 안의 `FS/data/log/bt/btsnoop_hci.log`를 추출했고 970,341 bytes였다.
- 당시 파싱 출력은 총 3,641 records를 표시했다. 이 수치가 모두 G435 버튼 패킷이라는 뜻은 아니다.
- G435 연결·이름 응답과 프로필 협상, 일부 RFCOMM AT 명령과 AVRCP 교환을 관측했다. 구체적 키·식별자·페어링 데이터는 문서에 복제하지 않는다.

## 관측과 결론의 제한

당시 어시스턴트는 “미디어 버튼 명령을 확인하지 못했다”, 이어 “현재 방식으로 재매핑 불가”라고 설명했다. 후속 대화에서 “이번 Android 시험에서 사용할 신호를 못 찾았다”는 제한된 판단으로 정정했다.

이 기록만으로 다음을 확정할 수 없다.

- 모든 버튼 누름이 기록 구간과 정확히 대응했는지.
- 패킷 분석이 모든 관련 채널·명령을 빠짐없이 해석했는지.
- G435 펌웨어가 어떤 호스트에서도 신호를 보내지 않는지.
- HCI 관측만으로 일반 앱에서 사용할 수 있는 입력 경로가 있는지.

## 현재 증거 보존 상태

2026-10-31 확인 시 `diagnostics/`는 비어 있고 위 ZIP·추출 로그 경로는 없다. 따라서 이번에는 원시 패킷을 다시 분석하지 못했다. 원본이 존재하는 것처럼 링크하거나 재분석 성공을 주장하지 않는다.

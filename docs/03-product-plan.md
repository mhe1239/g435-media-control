# 3) 제품 목표와 현재 상태

갱신: 2026-10-31, Asia/Seoul. 현재 단계는 실현 가능성 진단이다.

## A. 목적과 사용자 요구

G435를 쓰는 사용자가 Bluetooth로 연결한 Windows PC 또는 갤럭시에서 재생/일시정지, 다음/이전 곡, 앱별 알림 읽기를 이용할 수 있는지 검증한다.

- 사용자는 LIGHTSPEED USB 동글을 사용하지 않는다.
- ANC 등 하드웨어 추가가 필요한 기능은 범위에서 제외한다.
- G435의 기존 전원·페어링·사이드톤·음량 제한 조작을 보존한다.
- 휴대폰 버튼이나 별도 리모컨은 대안으로 언급됐지만 사용자가 채택한 방향이 아니다.

## B. 초기 조작 설계안

| 제안한 짧은 동시 누름 | 의도 | 상태 |
|---|---|---|
| 전원 + 음소거 | 재생/일시정지 | 제안만 존재, 구분 가능한 신호 미확인 |
| 전원 + 볼륨 + | 다음 곡 | 제안만 존재, 구분 가능한 신호 미확인 |
| 전원 + 볼륨 − | 이전 곡 | 제안만 존재, 구분 가능한 신호 미확인 |

`전원+음소거` 3초 이상은 Bluetooth 페어링으로 설명된 기존 기능이다. 재시험은 짧은 누름으로 제한한다. `음소거+볼륨`의 기존 사이드톤/제한 기능을 임의로 재사용하지 않는다.

## C. 지금까지의 결과

| 기능/관측 | 현재 판단 |
|---|---|
| Windows 볼륨 변화 | 2026-10-15, 2026-10-31 활성 G435 엔드포인트에서 +/−와 맞는 고정 단계 변화 확인. G435 조절 범위 = Windows `0.0`–`0.69167` |
| Windows 직접 키/HID | 해당 시험에서 G435 버튼이라고 입증된 직접 입력 없음 |
| Windows 음소거 | 해당 시험에서 엔드포인트 음소거 변화 미관측 |
| Android 일반 앱 수신 | G435 키 이벤트 없음. +/−는 STREAM_MUSIC 볼륨 변화로만 도착, 음소거는 신호 없음(2026-10-31) |
| Android 전원·마이크 짧은 누름 | 재생 중에도 G435가 폰에 보내는 패킷 없음. 음소거 3초 이상은 Bluetooth 연결 해제 후 재연결이라 제스처 불가. HCI snoop으로 확인(2026-11-01, [보고서](reports/261101-1605-10-android-power-mic-hci.md)) |
| Android 접근성 | capability 선언 보완 후 키 필터 작동 확인(2026-10-31) |

| 미디어 재매핑 | Android와 Windows의 재생/일시정지를 구현·실기기 확인. Windows는 Chrome·Spotify에서 확인(2026-11-01, [보고서](reports/261101-2312-11-windows-play-pause-gesture.md)). Windows 다음/이전 곡(`+−+`/`−+−`)은 Spotify·YouTube 재생목록에서 확인, YouTube 단일 영상은 페이지가 지원하지 않아 불가(2026-11-01). Android 다음/이전은 Chrome YouTube 재생목록·AudioSeeker·Samsung Music에서 확인(2026-11-01 23:56–11-02 00:01), 1회 Chrome이 넘김 지원을 끈 상태라 실패(원인 미확인) |
| 알림 읽기 | 요구사항 검토만 수행, 미구현 |

Windows 로그에서 00:07:39.320의 볼륨은 `0.43067 → 0.49342`, 00:07:44.216은 `0.49342 → 0.43067`이다. 사용자가 요청된 G435 +/−/음소거 시험 완료를 알려준 구간과 대응하지만, 오디오 값만으로 입력 발생 주체를 기술적으로 증명할 수는 없다.

## D. 마지막 미해결 상황과 다음 시작점

사용자는 이후 “G435의 +/−를 눌러도 볼륨이 안 올라갈 때가 있다”고 보고했다. 마지막으로 확인하려던 내용은 다음과 같다.

> 안 될 때 Windows 볼륨 숫자도 그대로인가, 아니면 숫자는 바뀌는데 실제 소리 크기만 그대로인가?

2026-10-31 답변은 “숫자도 그대로”였다. 같은 날 재현에서 + 4번 뒤 G435가 “따닥” 소리를 내며 멈췄고 Windows 값은 `0.69167`이었다. 무반응은 G435 자체 최대 도달로 설명된다([보고서](reports/261031-2004-08-windows-volume-max.md)). 이어진 시험에서 최소는 Windows 0%(알림음 없음)였고, PC로 69%를 넘겨도 G435 −는 헤드셋 단계값으로 되돌렸다. 강의 재생 중 재시험에서는 Hands-Free 전환 없이 누름 19건이 모두 반영됐지만 19:59 전환의 원인은 모르므로 볼륨 기반 제스처가 안정적이라고 결정하지 않는다.

Android에서는 접근성 선언 보완 뒤 재시험해, G435 +/− 방향 전환 제스처로 재생/일시정지를 구현했다([보고서](reports/261031-2341-09-android-play-pause-gesture.md)). 일시정지 중에는 무음을 최대 10분 재생해 Bluetooth 스트림을 유지해야 재개 제스처가 폰에 도착한다. Samsung Music·AudioSeeker·Chrome·Brave에서 확인했고, 실사용 중 오인식·배터리는 아직 확인하지 않았다.

## E. 알림 읽기 요구

- 사용자가 알림을 읽을 앱을 선택한다.
- 간단히 읽기는 앱 이름만, 자세히 읽기는 알림 내용을 읽는 방식이다.
- Galaxy Wearable의 Buds 전용 기능이 G435에도 적용된다고 가정하지 않는다.
- 별도 Android 알림 접근·TTS 방식은 후보일 뿐이다. 권한 안내, 잠금화면 민감 알림, 출력 경로, 중복 낭독 정책은 구현 전에 결정해야 한다.

## F. 다음 단계의 완료 기준

- 진단 도구의 대조 입력이 정상이며 실제 G435 입력과 출처가 구분된다.
- 볼륨 실패 조건을 재현하거나 최소한 발생 조건·관측 한계를 기록한다.
- 수신 경로의 안정성이 입증되기 전에는 일시정지·다음/이전 곡 매핑을 완성 기능으로 제공하지 않는다.
- 신호가 없다면 시험한 경로·장치·조건에 한정해 결과를 보고한다.
